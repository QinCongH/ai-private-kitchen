# AI 私厨 H5 前端技术方案与开发文档

本项目是一款基于 Next.js 的高级 AI 私厨定制 H5 移动端应用。本文档旨在规范前端技术选型、架构设计、核心组件实现以及接口联调逻辑。

---

## 一、 技术栈选型 (Tech Stack)

| 技术选型 | 方案 | 理由 |
| :--- | :--- | :--- |
| **框架 (Framework)** | **Next.js 16+ (App Router)** | 提供优秀的 SSR/SSG 能力，路由清晰，适合 H5 快速加载与 SEO |
| **样式 (Styling)** | **Tailwind CSS** | 极其适合快速构建微调、无缝微动效及响应式莫兰迪色系 |
| **语言 (Language)** | **TypeScript** | 提供严格的类型定义，确保与后端 API 数据契合时的稳定性 |
| **基础组件库** | **Radix UI / Shadcn UI** | 无样式、高可定制化的无障碍组件（Drawer、Dialog），方便注入高级感 |
| **状态管理** | **Zustand** | 轻量级状态管理，用于跨组件维护当前活跃的会话 ID 及历史列表 |
| **数据请求** | **SWR / TanStack Query** | 用于处理会话列表的实时刷新、缓存和局部乐观更新（Optimistic Updates） |

### 3. 底部输入与快捷标签组件 (Input & Quick Actions)

```tsx
// src/components/InputBar.tsx
'use client'

import { useState, useRef, useEffect } from 'react';
import { Mic, ArrowUp } from 'lucide-react';

interface InputBarProps {
  onSendMessage: (text: string) => void;
  isLoading?: boolean;
}

const QUICK_TAGS = [
  "Today's Menu",
  "Chef's Special", 
  "Seasonal",
  "Wine Pairing",
  "Quick Recipe"
];

export default function InputBar({ onSendMessage, isLoading = false }: InputBarProps) {
  const [inputValue, setInputValue] = useState('');
  const textareaRef = useRef<HTMLTextAreaElement>(null);

  // 自动调整输入框高度
  useEffect(() => {
    if (textareaRef.current) {
      textareaRef.current.style.height = 'auto';
      textareaRef.current.style.height = `${Math.min(textareaRef.current.scrollHeight, 96)}px`;
    }
  }, [inputValue]);

  const handleSend = () => {
    if (!inputValue.trim() || isLoading) return;
    onSendMessage(inputValue);
    setInputValue('');
  };

  const handleKeyDown = (e: React.KeyboardEvent) => {
    if (e.key === 'Enter' && !e.shiftKey) {
      e.preventDefault();
      handleSend();
    }
  };

  return (
    <div className="p-4 bg-chef-bg border-t border-white/10 space-y-3">
      {/* 横向可滑动快捷标签 */}
      <div className="flex items-center space-x-2 overflow-x-auto no-scrollbar py-1">
        {QUICK_TAGS.map((tag) => (
          <button
            key={tag}
            onClick={() => setInputValue(tag)}
            className="whitespace-nowrap text-xs bg-white/30 text-chef-text px-4 py-1.5 rounded-full border border-white/40 hover:bg-white/50 transition active:scale-95"
          >
            {tag}
          </button>
        ))}
      </div>

      {/* 大圆角核心输入框 */}
      <div className="flex items-end bg-white/40 border border-white/40 rounded-input p-2 pl-4 shadow-inner space-x-2">
        <textarea
          ref={textareaRef}
          rows={1}
          value={inputValue}
          onChange={(e) => setInputValue(e.target.value)}
          onKeyDown={handleKeyDown}
          placeholder="Ask your private chef..."
          disabled={isLoading}
          className="flex-1 max-h-24 bg-transparent border-0 focus:ring-0 focus:outline-none resize-none text-sm text-chef-text placeholder-chef-muted/60 py-1 font-sans disabled:opacity-50"
        />
        
        {/* 语音输入 */}
        <button className="p-2 text-chef-text hover:opacity-70 transition">
          <Mic className="w-5 h-5" />
        </button>

        {/* 发送按钮 */}
        <button
          onClick={handleSend}
          disabled={!inputValue.trim() || isLoading}
          className={`p-2.5 rounded-full text-white transition-all duration-300 shadow-md
            ${inputValue.trim() && !isLoading 
              ? 'bg-chef-accent opacity-100 scale-100 active:scale-95' 
              : 'bg-chef-accent/40 opacity-50 scale-95 cursor-not-allowed'
            }`}
        >
          <ArrowUp className="w-4 h-4" />
        </button>
      </div>

      <p className="text-[9px] text-center text-chef-muted/50 font-sans tracking-widest uppercase">
        AI Private Chef
      </p>
    </div>
  );
}
```

## 九、 后端联调方案 (API Integration)

### 0. 代理方案选型（重要）

**Next.js `rewrites` 会缓冲整个响应体再转发，无法逐帧透传 SSE 流。** 因此采用混合代理策略：

| 接口类型 | 代理方式 | 原因 |
|:---------|:---------|:-----|
| SSE 流式对话 (`/chat`) | **Route Handler** | Route Handler 基于 Web Streams API，`new Response(body)` 直接 pipe ReadableStream，不做缓冲 |
| REST 会话管理 (`/session/*`) | **rewrites** | 一次性返回 JSON，缓冲无影响 |

#### Route Handler 实现（`app/api/v1/agent/chat/route.ts`）

```typescript
export const runtime = 'nodejs';        // Node.js 运行时正确处理 ReadableStream pipe
export const dynamic = 'force-dynamic'; // 禁用静态优化和缓存

const BACKEND_BASE = process.env.NEXT_PUBLIC_API_BASE || 'http://localhost:3000';

export async function POST(request: Request) {
  const body = await request.text();

  const backendResponse = await fetch(`${BACKEND_BASE}/api/v1/agent/chat`, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Accept': 'text/event-stream',
      'Cache-Control': 'no-cache',
    },
    body,
    signal: request.signal,  // 客户端断开时同步中止后端请求
  });

  if (!backendResponse.ok || !backendResponse.body) {
    return new Response(
      JSON.stringify({ error: `Backend error: ${backendResponse.status}` }),
      { status: backendResponse.status || 502 },
    );
  }

  // 直接 pipe 后端 SSE 流，不缓冲
  return new Response(backendResponse.body, {
    status: backendResponse.status,
    headers: {
      'Content-Type': 'text/event-stream',
      'Cache-Control': 'no-cache, no-transform',
      'Connection': 'keep-alive',
      'X-Accel-Buffering': 'no',  // 防止 nginx 层缓冲
    },
  });
}
```

### 3. SSE 流式对话联调详解

#### 3.1 请求参数（对齐后端 ChatDto）

**POST** `/api/v1/agent/chat`

| 字段 | 类型 | 必填 | 说明 |
|:-----|:-----|:-----|:-----|
| `query` | `string` | 是 | 用户输入内容（1-4096 字符） |
| `session_id` | `string` | 否 | 会话 ID，不传则后端自动创建新会话 |
| `image_url` | `string` | 否 | 图片 URL，支持多模态输入 |

**前端类型定义（`types/chat.ts`）：**


**请求示例：**

#### 3.2 SSE 帧类型

后端 SSE 推送采用标准 `text/event-stream` 协议，每帧格式为 `data:{json}\n\n`。

| type | 含义 | messages | extra |
|:-----|:-----|:---------|:------|
| `waiting` | Agent 正在处理 | 提示文本（如"正在思考中..."） | `null` |
| `message` | LLM 流式输出的文本片段 | AI 回答正文 | `null` |
| `done` | 流式输出结束 | `""` | `SessionMeta` |
| `error` | 发生错误 | 错误描述 | `null` |

**SessionMeta 结构（仅 `done` 帧携带）：**

```typescript
interface SessionMeta {
  intent: string;        // 用户意图
  summary: string;       // 本轮对话摘要
  artifacts: string[];   // 产出物列表（如食谱名称）
  next_steps: string[];  // 建议的后续操作
}
```

#### 3.3 前端 SSE 解析核心逻辑（`lib/api.ts`）

```typescript
/**
 * POST /api/v1/agent/chat
 * 请求体对齐后端 ChatDto: { query, session_id?, image_url? }
 */
export async function streamChat(
  request: ChatRequest,
  callbacks: StreamCallbacks,
  signal?: AbortSignal,
): Promise<void> {
  const body: Record<string, string> = { query: request.query };
  if (request.session_id) body.session_id = request.session_id;
  if (request.image_url) body.image_url = request.image_url;

  const response = await fetch('/api/v1/agent/chat', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(body),
    signal,
  });

  const reader = response.body!.getReader();
  const decoder = new TextDecoder();
  let buffer = '';

  while (true) {
    const { value, done } = await reader.read();
    if (done) break;

    buffer += decoder.decode(value, { stream: true });
    const lines = buffer.split('\n');
    buffer = lines.pop() ?? '';

    for (const line of lines) {
      if (!line.trim().startsWith('data:')) continue;
      const frame: SSEFrame = JSON.parse(line.trim().slice(5));

      switch (frame.type) {
        case 'waiting':  callbacks.onWaiting?.(frame.messages); break;
        case 'message':  callbacks.onMessage?.(frame.messages); break;
        case 'done':     callbacks.onDone?.(frame); return;
        case 'error':    callbacks.onError?.(frame.messages); return;
      }
    }
  }
}
```

### 4. 会话生命周期流程

**`session_id` 由前端生成，必传。** 首次发消息时自动生成并绑定到当前会话窗口，后续消息复用同一 `session_id`。

```
前端生成规则：sess_{timestamp}_{random8}

用户首次发送消息
  │
  ├─ currentSessionId === null
  │    → 前端生成 session_id（generateSessionId()）
  │    → 立即写入 currentSessionId（与用户消息同步推入）
  │    → POST /api/v1/agent/chat { query, session_id, image_url? }
  │    → SSE 流正常返回
  │    → done 帧后将 session 加入本地 sessions 列表
  │
  ├─ currentSessionId !== null
  │    → POST /api/v1/agent/chat { query, session_id, image_url? }
  │    → 后端延续已有会话上下文
  │
  └─ 用户点击"新建会话"
       → 清空消息列表，currentSessionId 置为 null
       → 下次发消息时重新生成 session_id
```

```typescript
function generateSessionId(): string {
  return `sess_${Date.now()}_${Math.random().toString(36).slice(2, 10)}`;
}
```

### 5. 乐观更新策略

```
用户点击发送
  │
  ├─ ① 立即推入用户消息气泡（无需等待后端）
  ├─ ② 显示 AI typing indicator
  ├─ ③ 发起 SSE 流式请求
  │
  ├─ ④ 收到 waiting 帧 → 保持 typing 状态
  ├─ ⑤ 收到 message 帧 → 逐字追加到 AI 气泡（流式打字效果）
  ├─ ⑥ 收到 done 帧 → 渲染 SessionMeta 卡片，停止 typing
  │
  └─ 异常处理
       ├─ 网络错误 → AI 气泡显示"发送失败，请稍后重试"
       └─ 用户主动停止 → AbortController 中断流，保留已接收内容
```

### 7. SSE 流式实时预览（输入框区域）

前端通过 SSE 流式接收 AI 回复时，除了在聊天区域的 AI 气泡中逐字显示外，还在底部输入框区域实时渲染 AI 生成内容，形成"双区域同步流式展示"效果。

#### 数据流

```
SSE message 帧
  │
  ├─→ useChatStore.messages        → ChatTimeline   AI 气泡逐字追加
  └─→ useChatStore.streamingText   → InputBar       输入框上方实时预览
```

#### Store 实现

```typescript
interface ChatState {
  // ...
  /** SSE 流式接收中，AI 实时生成的文本（供输入框区域实时预览） */
  streamingText: string;
}

// onMessage 回调中同步更新
onMessage: (chunk) => {
  accumulated += chunk;
  set((state) => ({
    messages: state.messages.map((m) =>
      m.id === aiId ? { ...m, content: accumulated } : m,
    ),
    streamingText: accumulated,  // 同步更新预览文本
  }));
},

// done / error 时清空
onDone: () => set({ streamingText: '', isTyping: false }),
onError: () => set({ streamingText: '', isTyping: false }),
```

## 十、 开发注意事项

1. **移动端适配：** 使用 `100dvh` 替代 `100vh`，处理移动端浏览器地址栏问题
2. **安全区域：** 底部输入栏需适配 iPhone 底部安全区域
3. **键盘弹出：** 输入框聚焦时自动滚动到底部，避免键盘遮挡
4. **触摸反馈：** 使用 `active:scale-95` 提供触摸反馈
5. **性能优化：** 长列表使用虚拟滚动，避免大量 DOM 节点
6. **SSE 断线重连：** 当前实现不包含自动重连，生产环境建议增加重试逻辑
7. **会话持久化：** 前端 sessions 列表为内存状态，刷新后丢失；后端会话由 SQLite 持久化，可通过 session_id 重新加载
